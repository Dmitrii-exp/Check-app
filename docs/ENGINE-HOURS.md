# Учёт моточасов

## Работа с функцией

1. В «Задачах» нажать «Внести показания» или открыть «Внести моточасы» в карточке оборудования. Вносится общий счётчик, не часы за смену.
2. Руководитель создаёт действие ТО и выбирает «По моточасам», например 2000. При счётчике 3560 порог 4000, остаток 440.
3. При достижении 4000 сервер создаёт обычную задачу с прежним обязательным фотоотчётом. При 3999,9 задача ещё не создаётся.
4. После выполнения на 4000 следующий порог 6000. При позднем выполнении, например на 8500, следующий порог 10000; пропущенные обслуживания не записываются как выполненные.

Периодичность «По дням» сохранена. На одном оборудовании могут быть отдельные регламенты по дням и по моточасам. Моточасы не превращаются в выдуманные даты в календаре.

## Данные и безопасность

Добавлены nullable-поля счётчика и отдельная таблица журнала. Существующие регламенты получают тип days без изменения frequency. Чтение и запись ограничены компанией, подразделением и активностью оборудования по тарифу. Сотрудник вносит показания через RPC, не получает права редактировать оборудование.

Запись использует блокировку компании, блокировку строки и сравнение ожидаемого значения. Уменьшение, отрицательные/нечисловые значения и устаревшая запись отклоняются. В журнале сохраняются старое/новое показание, автор и время; повтор одинакового показания не добавляет дубликат. Новые пороги и показания при выполнении определяет сервер.

## Проверки

- Изолированный PostgreSQL/PGlite: реальная миграция, реальные ранее действовавшие guards и RLS, 3560→4000/440, 0, точный порог, дробные показания, просрочка, повтор, конфликт, уменьшение, чужая компания, истёкшая подписка, выполнение с фото и переход порога.
- Браузер с изолированным API: создание регламента/предпросмотр, ввод сотрудником, ошибка/повтор/ожидание, блокировка дублей, Escape и возврат фокуса, сохранение подразделения, 320/390/1440 px, обе темы.
- Пройдены проверки авторизации, пароля, команды, удаления компании, тайм-аутов, темы и мобильной навигации.
- DESIGN.md lint: 0 ошибок/предупреждений. Строгий внешний UI-сканер сохраняет 18 прежних замечаний (в том числе недетектируемые делегированные кнопки); новые поля не добавили замечаний. Это не заявление о полном аудите WCAG.

## Публикация и откат

Перед обновлением REG.RU используется обязательный FTPS-бэкап из deploy-reg-ru.yml. Определения серверных функций до изменения сохранены в engine-hours-schema-before.sql; это справочный снимок, не скрипт автоматического отката. После появления новых показаний/регламентов при откате фронтенда следует сохранить расширенную схему и генератор задач. Новую историю не удалять.

Android-релиз 1.2.11 должен пройти проверку содержимого и сертификата прежнего APK до публикации.
