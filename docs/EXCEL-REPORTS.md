# Отчёты Excel по подразделению

В разделе «Отчёты» выбрать «Подразделение для файла» и нажать «Скачать Excel». Руководитель сети выбирает доступное подразделение; руководитель подразделения — своё. Сотрудник не получает доступ к выгрузке. Запросы используют существующую RLS, данные не загружаются на сторонний сервер.

## Состав файла

- Сводка: выполнено, не выполнено, из них явно отмечено «Не выполнено», всего по сотрудникам / указанным исполнителям.
- Выполненные: ТО и разовые задачи, оборудование, сроки, дата выполнения, фактический исполнитель, отдельно отправитель отчёта, комментарий, порог и фактическая наработка, идентификатор задачи.
- Невыполненные: открытые задачи по текущую дату UTC включительно, статус, ответственный / указанный исполнитель, просрочка, причина, имя в отметке о невыполнении. Будущие открытые задачи исключены.

Экспорт за всё время на момент выгрузки; это не реконструкция состояния на историческую дату. Повторные фотоотчёты для одной задачи считаются один раз; сохранённый фотоотчёт имеет приоритет над временным pending-статусом задачи.

## Учёт людей

Исполнитель ТО берётся из worker_name, отправитель — из user_id. Имя однозначно сопоставляется с полным именем аккаунта; при отсутствии однозначного совпадения остаётся отдельная строка с пояснением. Неподтверждённые имена не выдаются за проверенную личность аккаунта. Разовые задачи учитываются по сохранённому назначению.

Открытые задачи учитываются по assigned_user_id; если назначения нет, но сохранено имя в результате «Не выполнено», учитывается указанное имя. Без назначения и имени исполнителя — отдельная группа. Общая задача не добавляется каждому сотруднику.

## Техническая реализация

report-export.js читает свежие таблицы tasks/completions/one_time_tasks/equipment и доступные profiles с явным фильтром компании и подразделения. Используется keyset-пагинация по id и реальный размер ответа; проверены 1201 запись и нестандартный лимит сервера 100 записей. При ошибке API или смене аккаунта файл не выдаётся частично.

ExcelJS 4.4.0 закреплён в package-lock.json; браузерная сборка копируется локально при build:mobile и загружается только по запросу отчёта. Формат XLSX: даты/моточасы — типизированные значения, сводка — COUNTIF/COUNTIFS/SUM с проверенными cached results, автофильтры, закреплённые заголовки и перенос текста. Пользовательские строки не превращаются в формулы.

В браузере используется Blob download. В Android APK 1.2.13 файл записывается в закрытый cache приложения и передаётся пользователю через системное меню сохранения/Share. Плагины Filesystem 8.1.5 и Share 8.0.3 закреплены; доступа к общему хранилищу не запрашивается. Пользователь сам выбирает приложение / место сохранения.

## Проверки

- test-report-export.mjs: подсчёты, назначенные/общие/явно невыполненные задачи, отправитель и исполнитель, дубли, старые отчёты, чужое подразделение/компания, пустые данные, будущие задачи, пагинация, ошибки, формулы/даты/числа, сохранение в cache и передача в Share (stub).
- test-report-export-ui.mjs: реальные XLSX-загрузки Chromium с изолированным Auth/API, разные подразделения, 501 разовая задача, пустой файл, ошибка/повтор, блокировка дублей, роли, ширины 320/390/1440 и обе темы.
- Независимое чтение XLSX через openpyxl: 3 листа, сверка cached totals.
- Регрессии моточасов, авторизации и мобильной навигации пройдены. Схема базы, Auth, платежи и права доступа не меняются.
- Внешний строгий UI-аудит сохраняет прежние 18 замечаний; DESIGN.md lint — 0 ошибок/предупреждений.

Перед публикацией используется прежний обязательный FTPS-бэкап. Новый APK проверяет наличие модулей отчёта, ExcelJS и нативных плагинов; сертификат сравнивается с прежним подписанным APK. Работа системного меню на физическом Android-устройстве в этой среде не тестируется.
