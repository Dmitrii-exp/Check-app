# Check App — аудит 2026-09

## Этап 1 — безопасность базы

Проверены 11 SECURITY DEFINER RPC:
- `bootstrap_company`
- `current_company_id`
- `current_company_is_unlimited`
- `current_department_id`
- `current_role`
- `grant_unlimited_company`
- `is_super_admin`
- `is_unlimited_company`
- `join_company_by_invite`
- `list_companies_for_super_admin`
- `revoke_unlimited_company`

Проверено:
- RPC доступны только `authenticated`, не `anon`.
- SECURITY DEFINER-функции используют `SET search_path TO ''`.
- административные RPC дополнительно проверяют `is_super_admin()`.
- RLS включён на всех основных таблицах приложения.
- прямые записи в `super_admins` и `owner_companies` для `authenticated` отозваны.
- прямые записи в `companies` и `subscriptions` для `authenticated` отозваны; чтение сохранено для текущей компании.
- `super_admins` ограничен чтением собственной записи для super-admin.

Важно: предупреждение Supabase о SECURITY DEFINER само по себе не означает наличие уязвимости. Эти функции используются для безопасного доступа к данным через RLS-helper и административные проверки. Удалять SECURITY DEFINER без отдельного теста нельзя — это может сломать регистрацию и RLS.

## Этап 2 — функциональный аудит JS

Проверены основные зоны кода: Auth/OTP, hydrate/sync Supabase, роли, подразделения, оборудование, регламенты ТО, задания, выполнения, фото и подписки. Добавлен статический аудит:

```text
node scripts/audit-js.mjs
```

Он проверяет inline-обработчики HTML на отсутствующие функции и ищет серверные secret/service-role токены в клиентских файлах.

Известный технический долг, не менялся без отдельного теста: старый Enter-listener OTP ссылается на `pendingOtp`/`verifyPendingOtp`.
