# Обновления Android Check App

## Один раз: настройка подписи
Создайте собственный Android keystore и **сохраните его резервную копию вне GitHub**. Если ключ потерян, обновления поверх установленных приложений станут невозможны.

В Settings → Secrets and variables → Actions добавьте:
- `ANDROID_KEYSTORE_BASE64`: содержимое keystore, закодированное base64 без переносов строк;
- `ANDROID_KEYSTORE_PASSWORD`: пароль хранилища;
- `ANDROID_KEY_ALIAS`: псевдоним ключа;
- `ANDROID_KEY_PASSWORD`: пароль ключа.

**Важно:** если пользователи уже установили debug APK, новый release APK с другим сертификатом не установится поверх него. Для перехода на постоянную подпись потребуется переустановка; данные, хранящиеся локально, могут быть удалены. Данные Supabase сохраняются в облаке.

## Публикация
1. Обновить версию в `package.json`, `js/update-center.js` и `public/app-updates.json`, а также описание изменений в `public/app-updates.json`.
2. В GitHub Actions запустить **Publish signed Android update** → **Run workflow**.
3. Workflow соберёт подписанный release APK, создаст GitHub Release с заметками и прикрепит `Check-App-vX.Y.Z.apk`.
4. Кнопка «Установить обновление» в установленном Android-приложении обнаружит новый опубликованный релиз и откроет системную установку Android.

Приложение не может без участия пользователя разрешить установку из неизвестных источников или обойти системное подтверждение. На iPhone используется PWA и обновление сайта, не APK.

Не публикуйте debug APK в качестве автоматического обновления. Подписанные релизы публикуются только при наличии всех секретов.
